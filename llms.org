* Working with imports

The lines under Imports are Claude Code imports.  They are not org links.
Claude Code inlines each named file before the first turn.  ~CLAUDE.md~ is a
symlink to this file.

An import is a line that is exactly an at sign followed by a path.  Each import
is a paragraph of its own.  Do not replace an import with an org link.  A link
can be skipped and an import cannot.

* Documents

New documents are org-mode files.

Use ~:exports code~ on a source block that only shows code.

No file lists in documentation.

* Prose rules

These apply to comments, option descriptions, org documents, commit bodies, and
replies.  The reasoning behind each one is in rust-template's
[[https://github.com/LoganBarnett/rust-template/blob/main/docs/contribution-rationale.org][=docs/contribution-rationale.org=]].

1. Sentences are short.  One idea each.  About twenty words.
2. Punctuation is ASCII.  No em dashes.  No semicolons.  No parentheses.
3. A comma sets off one leading clause or separates a list.  Anything else is
   two sentences.
4. Comments are complete sentences wrapped at 80 columns.
5. Two spaces follow sentence-ending punctuation.
6. Open with the conclusion.  The mechanism comes after, or not at all.
7. A fact lives at the lowest level where it applies.  A line of code is the
   lowest and the README is the highest.  A workaround is explained on the line
   it guards, never above it.
8. A summary states the outcome.  It never lists the steps.
9. A comment states what the code cannot.  If the code could regenerate the
   comment, delete the comment.
10. Do not describe code that no longer exists.  If the obvious approach fails,
    state the fact that breaks it.
11. A number that was a coin flip says so.
12. When unsure whether to write a comment, do not.
13. Draft prose longer than a paragraph in a scratch file.  Rewrite it against
    this list.  Only the rewrite lands.
14. Lists are numbered whenever the format allows.  A number lets a reader refer
    to an item.

* Nix

** New files and flake visibility

A flake cannot see an untracked file.  Use ~git add --intent-to-add~ on a new
file.  This leaves an unstaged version to review.

* Formatting

~treefmt~ formats the tree.  Run it before offering a change.
