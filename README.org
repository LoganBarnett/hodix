hodix is a set of Nix modules and configurations for running a self-contained IT
center, or a hodon in project terms.  It is meant for a household or a small
business.

* Hodons

A hodon is a network built from hodix.  A hodon manages your local network.
They give you a sort of personal cloud suite.

* User Benefits

A hodon provides benefits depending on your use case.  Here are a few.

** Households

There's no EULA here where you give up all rights to your photos so they can be
used for AI training.  Don't subscribe to platforms that can yank or alter
features at any time.  Don't place your data on platforms that go out of
business, or delete your data because of a lapsed payment.

** Home Labs

Don't maintain a home laboratory where you implement some pet feature and burn
out on the rest.  Build a hodon and use it to springboard your k8s cluster you
wanted to play around with.  Enjoy not having to set up things like SSO, or
having to spend a week or two every year updating the software.

** Small Businesses

Enjoy the kind of configurations that the big businesses get, without needing to
fund an IT department.

* Somewhat Quick Start

You will need:

1. [[https://nixos.org/download][Nix installed]] on the workstation that will run this setup.
2. A machine you can dedicate as the primary server host for this hodon.  The
   machine will be repartitioned, and thus lose all data.
3. Removable + bootable media such as a USB thumb drive.
4. ~git~, if somehow your OS doesn't stock it.

Emit a Flake from our template. ~<dir>~ is the directory of the git repository /
Flake that will be created:

#+begin_src sh :results none :exports code
mkdir <dir> && cd <dir>
git init
nix flake init --template github:LoganBarnett/hodix
git add --all
#+end_src

Edit the ~facts.nix~ file to conform to your network, and name it.  We use
~home~ as our example hodon name, and ~balcony~ as the primary host's name.  We
highly recommend you use a different set of names.  See $path for example naming
patterns for the hodon itself and a series of suggestions for hostnames.

You need to setup a host and a user.  The user being you, the administrator of
this hodon.  You can add other administrators later, or hand over the capability
to others easily.

After editing the facts, we have this:

#+begin_src nix :results none :exports code
# The hodon.  Everything hodix runs is derived from this file.
{
  hodon = {
    name = "home";
    defaultHost = "balcony";
    networks.main.ipv4 = {
      cidr = "10.10.0.0/24";
      # The router.
      gateway = "10.10.0.1";
    };
    hosts.balcony = {
      system = "x86_64-linux";
      interfaces.main = {
        ipv4.address = "10.10.0.9";
        # The machine's hardware address.  Use `ip link` to see it.
        macAddresses = [ "00:00:5e:00:53:01" ];
      };
    };
    users.ada = {
      fullName = "Ada Lovelace";
      groups = [ "family" ];
    };
    groups.family = { };
  };
  hodix = {
    tls.root.subject = {
      country = "US";
      state = "Oregon";
      location = "Portland";
    };
  };
}
#+end_src

We also have a ~hosts/balcony.nix~ file in our new repository.  In there, we
need to setup hardware profiles from ~nixos-generate-config~ and a ~disko~
partition table, and perform the NixOS installation itself.  This will get you
an image:

#+begin_src sh :results none :exports code
curl --location --output nixos-minimal.iso \
  https://channels.nixos.org/nixos-26.05/latest-nixos-minimal-x86_64-linux.iso
#+end_src

Assuming a USB thumb drive, flash the image thusly in Linux:

#+begin_src sh :results none :exports code
# lsblk shows which /dev/sdX is the thumb drive.
sudo dd if=nixos-minimal.iso of=/dev/sdX bs=4M status=progress conv=fsync
#+end_src

Or on macOS:

#+begin_src sh :results none :exports code
# diskutil list shows which /dev/diskN is the thumb drive.
diskutil unmountDisk /dev/diskN
sudo dd if=nixos-minimal.iso of=/dev/rdiskN bs=4m
diskutil eject /dev/diskN
#+end_src

Connect the thumb drive to your main machine, and boot it.  Keep in mind that
the next steps will irreversibly destroy all data on this machine.  Backup
anything you want to keep before proceeding.

The NixOS installer should boot.  From there you will be presented with a user
and a password.  These are temporary values.  Once those are setup, return to
your workstation and run this get the hardware profiles for your main host:

#+begin_src sh :results none :exports code

#+end_src

Now we install NixOS on the host itself, using our declaration we've setup.
This will require the password you stood up earlier.

#+begin_src sh :results none :exports code
nix develop
hodix-install balcony nixos@<ip>
#+end_src

Next, reconfigure your router to cease DNS and DHCP.  How this is specifically
done is not covered in this guide.

Boot the main machine.  Once it is fully booted, reconnect to the network to get
your new DHCP lease from the server that now operates your network.

Trust the TLS certificate in your flake for your workstation.

Browse to ~https://nextcloud.home.hodon.internal~, substituting ~home~ for your
hodon's name.

To test that it all works, login with the user you defined in ~facts.nix~.  You
can use the following to get the initial password of your user:

#+begin_src sh :results none :exports code
agenix view secrets/generated/ada-ldap-password.age
#+end_src

Once you have logged in successfully, you have demonstrated full functionality.

* Principles

By creating a hodon you will be standing on these principles:

+ Privacy :: Everything is encrypted.  Your local network traffic, your traffic
  to other hodons, your backups.
+ Resilience :: Your data is completely backed up, incrementally.  Nobody can
  take away your data.
+ Control :: All of the hodix code is open source, and it is designed with
  extension and configuration in mind.
+ Reproducible :: Configurations do not expire with age.  Packages are kept
  locally.  You can always rebuild from scratch without it also needing to be an
  upgrade project.
+ Federated :: Connect your network with others of its kind, peer to peer, one
  at a time.  Grant explicit access, and take it away with zero notice.


* Free Features

A hodon enjoys all of these features with minimal effort on your part.

** SSO

Single Sign-On is the capability to have a single account that can log in
anywhere.  A more powerful version of that is having a single-session that spans
multiple applications.  Hodix supports both where the applications involved
support it.

The authority is an LDAP directory using OpenLDAP.  OIDC SSO is handled via
Authelia so the LDAP directory remains the system of record.

** RBAC

Role Based Access Control places permissions into a grouping called a role, and
users are assigned roles.  This decouples users from the systems they want to
consume in a way that is easy for administrators to reason about who has
permissions to what.

For example: Imagine Alice and Bob are users on your hodon.  You want Alice to
be able to use the 3D printer on the hodon, but Bob can only look.  The 3D
printer server (typically OctoPrint) can have a ~3d-printers-viewers~,
~3d-printers-operators~, and ~3d-printers-administrators~ groups it looks for to
allow various permissions.  You give Alice the operators group, Bob the viewers
group, and yourself the administrators group.  Some applications allow for very
fine grained permissions.  You can bundle them together into a group by having
groups be members of groups.  So in our 3D printer example,
~3d-printers-operators~ could be a member of ~3d-printers-viewers~ so it gets
all of the viewing permissions, and also it is a member of
~3d-printers-operations-print-start~, ~3d-printers-operations-print-stop~, and
~3d-printers-operations-print-pause~ to allow printing operations.

Hodix supports RBAC via group nesting in LDAP.  See [[*SSO][SSO]] for how that LDAP
extends into OIDC and other modern authentication concepts.

** Backups

Local backups are made daily and incrementally.  Incremental backups save
enormous amounts of space by only recording what changed between backups.

Take a situation where you have a lot of photos, but you want to scrub the
location data from them.  They've been backed up already.  After you do the
scrub, a normal backup system would have to hold onto both the original copies
of the photos and the scrubbed copies.  So effectively, you would have the
photos stored twice.  With incremental backups, the system only records that the
new photo is different from the old photo in that the new photo has some data
removed.

Hodix uses Restic to handle backups.  Backups are encrypted "at rest", meaning
the backups are inaccessible to anyone who doesn't hold the key to the backups.


** Personal Cloud

Sync, share, search, and catalog files.  This includes photos, which get
automatically cataloged by locally run machine learning.  Use a personal or
shared calendar with your favorite calendar tool.  Automatically sync your
photos and notes over your smart phone.

This personal cloud work is made possible via Nextcloud.

** VPN

Make sure you can always access your files, calendars, and email with a VPN
straight to your home.  Side step annoying roaming issues with licensing and
tailored views by tunneling from another region to your household.

VPN is managed via WireGuard.

** NFS

If your main physical machine cannot connect directly to your television, setup
a new host in the hodon and have it gain access to your media via NFS.

NFS is authenticated and encrypted via local WireGuard configurations that are
automatically created when a consumer uses the NFS share.

** Federated Hodons

Peer to peer connections to other hodons allows selective access between the two
hodons.  The connection requires both hodon administrators to agree to the
connection, and can be revoked at any time by either party.  Users from the
remote hodon can be given fine grained permissions in the local hodon as if they
were local users.
