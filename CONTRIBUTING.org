hodix is both a product and an API for other people's networks.  The bar for a
change is higher than in a personal configuration.

* Public surface

Every option, flake output, and importable file path is public API.  Changing
one breaks other people's hodons.

1. Every option has a type and a description.
2. A type is as strict as its meaning allows.  A constraint can be relaxed
   later.  It cannot be tightened without breaking someone.
3. Nothing carries a site, family, or owner name.  Names describe roles.

*** Initialisms

Use Pascal initialisms such as ~Url~ when authoring new camel case identifiers.
Do not preserve them as ~URL~.

* Tests

Every module lands with tests.  Tests live under ~tests~ and run through ~nix
flake check~.  Checks that reject bad inputs needs a test showing the rejection.

GitHub runs ~nix flake check~ and ~treefmt --fail-on-change~ on every pull
request.  Both must pass before a merge into ~main~.  The rule lives in
~.github/branch-protection.json~ and is applied by hand, because the token a
workflow runs with cannot administer branch protection:

#+begin_src sh :results none :exports code
gh api --method PUT repos/LoganBarnett/hodix/branches/main/protection \
  --input .github/branch-protection.json
#+end_src

* Documentation

Documents are org-mode files.  Every document is reachable by following links
from ~README.org~.  Each link carries a one-line summary.  The summary lets a
reader decide whether to follow the link.
